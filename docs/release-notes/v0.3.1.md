A test of the update mechanism introduced in v0.3.0, and the first release built by CI rather than on a laptop.

No functional changes to the app itself. If you're on v0.3.0, Shota should offer you this one automatically — which is the entire point of it existing.

## Under the hood

- Releases are now built by GitHub Actions from a tagged commit, with the update signing key held as a repository secret. Previously a release depended on remembering to pass that key by hand, and forgetting it produced a release that looked completely normal while silently breaking updates for everyone already installed.
- The update signature is now taken as a separate step after the build, rather than during it, so Authenticode code signing can be slotted in between the two once it's available. Signing in the other order would describe a file that no longer exists and every client would reject the update.
